# Review guidelines

What to look for when reviewing a pull request here. The `PR Review` workflow
posts lint and type findings inline automatically; everything below is the part
that still needs a person.

See [CLAUDE.md](CLAUDE.md) for the conventions these rules protect.

## Always check

- **Access control.** Every page loader and server action touching garden data
  calls `requireGardenAccess(gardenId, action)` from `src/lib/guards.ts`. A new
  query that reads a garden-scoped table without it is a data leak, not a style
  problem. Non-members must get "not found", never "forbidden".
- **Input validation.** Server actions and route handlers parse their input with
  a Zod schema from `src/lib/validation.ts` before touching the database. Client
  checks are a convenience, never the boundary.
- **Error handling on async paths.** Server actions return `ActionResult` rather
  than throwing; `error` must be a key that exists in both message catalogs.
- **No `any`.** Prefer inference, `unknown` with narrowing, or the Drizzle
  `$inferSelect` / `$inferInsert` types. Flag `as` casts that discard a union.
- **Copy is translated.** No user-facing string outside `messages/lt.json` and
  `messages/en.json`. Both files must stay key-for-key identical.
- **Dates.** Garden data is date-only (`yyyy-MM-dd`) and pinned to
  `Europe/Vilnius` via `src/lib/dates.ts`. `new Date()` for "today" is a bug —
  it uses the device clock.
- **Secrets.** Nothing sensitive in a `NEXT_PUBLIC_` variable; those are inlined
  into the browser bundle.

## Authentication changes

- Sign-in and password reset must not reveal whether an address is registered.
- Password hashing and reset-token handling belong in `src/lib/passwords.ts`.
  Reset tokens are stored only as a hash.
- `callbackUrl` and any other redirect target must be a relative path.

## Mobile and accessibility

- Interactive targets at least 44×44px; body text at least 16px.
- New interactive elements are keyboard reachable and have a visible focus ring.
- Prefer skeletons over spinners.

## Do not comment on

- `src/components/ui/**` — generated by the shadcn CLI. Review only deliberate
  edits to it, such as the added `touch` button size.
- `drizzle/**` — generated migrations. Review `src/db/schema.ts` instead; the
  SQL is its output.
- `.next/**`, `node_modules/**`, `package-lock.json`.

## Before approving

`npm run typecheck`, `npm run lint`, `npm test` and `npm run format:check` all
pass — CI enforces this, but a green tick is not a substitute for reading the
diff. Schema changes need a generated migration committed alongside them.
